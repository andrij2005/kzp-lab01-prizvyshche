Ознайомлення з базовою інфраструктурою розробки Java-застосунків (JDK 21 LTS, Apache Maven, JUnit 5, SpotBugs, Git, GitHub Actions), набуття практичних навичок створення кросплатформних консольних програм для обробки текстових табличних даних (CSV), налаштування автоматичної збірки, статичного аналізу коду, модульного тестування та автоматичного CI/CD.

## 2. Постановка задачі (Варіант № 1)
Необхідно розробити консольну Java-програму, яка зчитує текстовий файл у форматі CSV (`data/input.csv`), проводить валідацію рядків, формує статистичні показники за коректними записами та виводить звіт у консоль та файл (`out/report.txt`).

* **Предметна область:** Каталог книжок
* **Формат запису CSV:** `назва;автор;сторінки;ціна` (розділювач — крапка з комою `;`, кодування — UTF-8).
* **Необхідні статистичні показники:**
  1. Кількість коректних записів (`validCount`);
  2. Середня кількість сторінок у книзі (`avgPages`);
  3. Максимальна ціна книги (`maxPrice`);
  4. Загальна вартість усіх книжок каталогу (`totalPrice`).

## 3. Структура програми та опис класів
Проєкт реалізовано на Java 21 LTS із дотриманням стандартної структури Maven-проєкту.

### Дерево проєкту:
```text
kzp-lab01-vozniak/
├── pom.xml
├── README.md
├── REPORT.md
├── LAB01_CONTEXT.md
├── data/
│   └── input.csv
├── src/
│   ├── main/
│   │   └── java/
│   │       └── ua/lpnu/kzp/
│   │           └── Main.java
│   └── test/
│       └── java/
│           └── ua/lpnu/kzp/
│               └── MainTest.java
├── out/
│   └── report.txt
└── target/
```

### Основні класи:
* **`ua.lpnu.kzp.Main`** — головний службовий клас програми.
  * `main(String[] args)` — точка входу, обробляє CLI-аргументи (`--input`, `--output`, `--help`), викликає читання CSV, валідацію рядків, розрахунок статистики, форматування звіту за допомогою `StringBuilder` і `Locale.ROOT` та вивід у консоль / файл `out/report.txt`.
* **`ua.lpnu.kzp.MainTest`** — клас модульного тестування (JUnit 5).
  * `testAverageCalculation()` — верифікація точності арифметичних розрахунків середнього значення сторінок з допуском `0.0001`.
  * `testCsvParsingLogic()` — перевірка коректності розбиття CSV-рядка методом `split(";", -1)` і зчитування полів.

## 4. Інфраструктура проєкту (Maven, Java 21, CI/CD)
Проєкт налаштовано за допомогою інструменту автоматизації збірки **Apache Maven 3.9.x**:

* **Версія Java:** Java 21 LTS (`<maven.compiler.release>21</maven.compiler.release>`).
* **Модульне тестування:** JUnit Jupiter 5.12.2 (scope `test`).
* **Статичний аналіз:** `spotbugs-maven-plugin` (4.9.2.0) — перевіряє потенційні баги у байткоді під час фази `verify`.
* **Створення виконуваного JAR:** `maven-shade-plugin` (3.6.0) — формує об'єднаний артефакт `lab01-1.0.0-all.jar` з указанням `Main-Class` у маніфесті.
* **Автоматизація CI/CD (GitHub Actions):** Налаштовано workflow `.github/workflows/ci.yml`, який запускає комбінацію тестів і перевірку `mvnw verify` на матриці з 3 операційних систем: `ubuntu-latest`, `windows-latest`, `macos-latest`.

## 10. Відповіді на контрольні питання

1. **Що таке JDK, JRE та JVM? Назвіть їхні основні відмінності.**
   * **JVM (Java Virtual Machine)** — віртуальна машина, яка виконує байткод Java (.class) і забезпечує кросплатформність.
   * **JRE (Java Runtime Environment)** — середовище виконання, що містить JVM та стандартні бібліотеки класів, необхідне для запуску готових програм.
   * **JDK (Java Development Kit)** — комплект розробника, який включає JRE, компілятор `javac`, інструменти відлагодження, документування та збірки.

2. **Які основні переваги та особливості використання Java 21 LTS?**
   * Java 21 — це версія з довготривалою підтримкою (LTS). Вона забезпечує високу стабільність, нові можливості мови (Pattern Matching, Record Patterns, Virtual Threads, Sequenced Collections) та високу продуктивність JVM.

3. **Що таке Apache Maven і для чого він використовується?**
   * Apache Maven — це інструмент автоматизації збірки проєктів, управління залежностями та декларативного опису інфраструктури через файл `pom.xml`.

4. **Яка роль файлу `pom.xml` у Maven-проєкті?**
   * `pom.xml` (Project Object Model) — це конфігураційний файл, який описує координати проєкту (groupId, artifactId, version), версію Java, залежності, плагіни та фази збірки.

5. **Що таке Maven Wrapper (`mvnw`) і навіщо він потрібен?**
   * Maven Wrapper дозволяє запускати збірку проєкту без попереднього встановлення Maven на комп'ютер розробника або CI-сервер, гарантуючи використання однієї чітко зафіксованої версії Maven.

6. **Які основні фази життєвого циклу збірки Maven ви знаєте?**
   * `clean` (очищення target), `validate` (перевірка проєкту), `compile` (компіляція коду), `test` (запуск модульних тестів), `package` (упаковка в JAR), `verify` (перевірка якісних критеріїв/SpotBugs), `install` (збереження в локальний репозиторій).

7. **Для чого призначений плагін `maven-surefire-plugin`?**
   * Для автоматичного пошуку та запуску модульних тестів (JUnit) під час фази `test`.

8. **Навіщо використовується `spotbugs-maven-plugin`?**
   * Для статичного аналізу компільованого байткоду Java з метою виявлення потенційних помилок, витоків ресурсів або порушень стандартів кодування.

9. **Що таке Fat JAR / Executable JAR і як його створює `maven-shade-plugin`?**
   * Це автономний JAR-архів, який містить компільовані класи проєкту та всі необхідні залежності, а також вказаний `Main-Class` у маніфесті для запуску командою `java -jar`.

10. **Що таке JUnit 5 та яка його структура?**
    * JUnit 5 — це фреймворк для модульного тестування Java-додатків. Складається з JUnit Platform (основа), JUnit Jupiter (нова модель програмування й анотації) та JUnit Vintage (підтримка JUnit 3/4).

11. **Чим анотація `@Test` відрізняється від інших анотацій JUnit?**
    * Позначає метод як тестовий випадок, який має бути виконаний тестовим фреймворком.

12. **Навіщо використовується параметр `Locale.ROOT` під час форматування чисел у Java?**
    * Для забезпечення незалежного від регіональних налаштувань ОС форматування (наприклад, гарантоване використання крапки як десяткового розділювача у `double`).

13. **Чому для розбиття CSV-рядка слід використовувати `split(";", -1)`?**
    * Параметр `-1` зберігає кінцеві порожні поля, що дозволяє коректно виявляти відсутні значення в CSV-записах, а не відкидати їх.

14. **У чому різниця між `String.isEmpty()` та `String.isBlank()` в Java?**
    * `isEmpty()` повертає `true`, якщо довжина рядка 0. `isBlank()` повертає `true`, якщо рядок порожній або містить лише пробільні символи (пробіли, табуляції).

15. **Як працює клас `StringBuilder` і чому він ефективніший за конкатенацію рядків `+` у циклах?**
    * `StringBuilder` використовує виділений змінюваний буфер символів, у той час як оператор `+` створює новий об'єкт `String` при кожній операції, що призводить до значних перевитрат пам'яті.

16. **Що таке `Path.of()` та `Files` у Java NIO?**
    * `Path.of()` створює кросплатформний об'єкт шляху до файла, а `Files` надає статичні методи для читання, запису, перевірки існування та маніпуляцій з файлами.

17. **Що таке Система контролю версій (Git) і яка її мета?**
    * Це розподілена система, яка відстежує зміни у вихідному коді, дозволяє повертатися до попередніх станів та організовує паралельну роботу декількох розробників.

18. **Що таке GitHub Issues та GitHub Pull Requests?**
    * **Issues** — інструмент для відстеження завдань, помилок та нових фіч.
    * **Pull Requests (PR)** — механізм пропозиції змін із гілки розробки в основну гілку `main` із можливістю проведення код-рев'ю.

19. **Що таке GitHub Actions та CI/CD?**
    * **CI/CD (Continuous Integration / Continuous Delivery)** — автоматичне збирання та тестування коду. **GitHub Actions** — сервіс автоматизації workflows безпосередньо у репозиторії GitHub.

20. **Що означає команда `Closes #1` в описі Pull Request у GitHub?**
    * Ця команда автоматично закриває вказане Issue №1 після злиття (merge) даного Pull Request в основну гілку `main`.
