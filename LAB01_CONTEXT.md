# Технічний контекст лабораторної роботи №1

Документ описує фактичну структуру, конфігурацію та поведінку проєкту. Він призначений для технічного ознайомлення іншої ШІ-моделі без доступу до робочої копії.

## 1. Глобальний огляд проєкту

- **Предметна область:** обробка табличних даних каталогу книжок.
- **Варіант:** Варіант 1 — Каталог книжок.
- **Мета програми:** консольна Java-програма читає CSV-подібний файл, перевіряє рядки, обчислює статистику за коректними записами та показує звіт у консолі й записує його у файл.
- **Вхідний файл за замовчуванням:** `data/input.csv`.
- **Файл результату за замовчуванням:** `out/report.txt`.
- **Версія Java:** Java 21 LTS; Maven-компіляція налаштована на `release 21`.
- **Версія Apache Maven:** серія 3.9.x; у середовищі виконання проєкту доступний Maven 3.9.15. Версія Maven не фіксується у `pom.xml`.
- **Тип артефакту:** `jar`, координати Maven: `ua.lpnu.kzp:lab01:1.0.0`.
- **Головний клас:** `ua.lpnu.kzp.Main`.

## 2. Архітектура та розташування файлів

### Дерево проєкту

```text
kzp-lab01-prizvyshche/
├── pom.xml
├── README.md
├── REPORT.md
├── LAB01_CONTEXT.md
├── data/
│   └── input.csv
├── src/
│   ├── main/
│   │   └── java/
│   │       └── ua/lpnu/kzp/
│   │           └── Main.java
│   └── test/
│       └── java/
│           └── ua/lpnu/kzp/
│               └── MainTest.java
├── out/                         # створюється під час запуску програми
│   └── report.txt               # результат роботи програми
└── target/                      # генерується Maven; не є вихідним кодом
    ├── classes/
    ├── test-classes/
    ├── surefire-reports/
    └── ...                      # JAR, SpotBugs-звіти та інші результати збірки
```

### Призначення каталогів

- `data/` — вхідні дані для програми. Файл читається у UTF-8.
- `src/main/java/` — основний код застосунку. Шлях пакета `ua/lpnu/kzp` відповідає оголошенню `package ua.lpnu.kzp;`.
- `src/test/java/` — тести JUnit Jupiter. Maven Surefire знаходить і запускає їх під час фази `test`.
- `out/` — каталог для звіту, який створюється програмою під час виконання, якщо його ще немає.
- `target/` — стандартний вихідний каталог Maven для класів, JAR, звітів і проміжних файлів. Його видаляє фаза `clean`.

## 3. Пофайловий детальний розбір

### `pom.xml`

Це Maven POM проєкту.

- Координати: `groupId=ua.lpnu.kzp`, `artifactId=lab01`, `version=1.0.0`.
- `packaging=jar` означає створення JAR-артефакту.
- `maven.compiler.release=21` обмежує компіляцію мовними/API можливостями Java 21 та задає сумісну версію класів. Це ціль проєкту; її не слід змінювати без прямої вимоги власника.
- `project.build.sourceEncoding` і `project.reporting.outputEncoding` задані як UTF-8, важливо для українських текстів.
- Єдина пряма залежність — `org.junit.jupiter:junit-jupiter:5.12.2` зі scope `test`. Вона потрібна для анотації `@Test` і перевірок у тестах, але не є runtime-залежністю основного застосунку.

Плагіни:

1. **`maven-compiler-plugin` 3.13.0** — компілює production- і test-код. Фактичну версію цільового Java API бере з властивості `maven.compiler.release=21`.
2. **`maven-surefire-plugin` 3.5.2** — запускає модульні тести під час фази `test`. Використовує автоматично визначений JUnit Platform provider.
3. **`spotbugs-maven-plugin` 4.9.2.0** — виконує статичний аналіз байткоду. Goal `check` прив'язаний до фази `verify`; знайдені порушення можуть завершити Maven-збірку помилкою.
4. **`maven-shade-plugin` 3.6.0** — на фазі `package` створює додатковий об'єднаний JAR із classifier `all`. `ManifestResourceTransformer` записує головний клас `ua.lpnu.kzp.Main` у маніфест, що дозволяє запускати цей артефакт через `java -jar`.

У `pom.xml` немає Spring, бази даних, CSV-бібліотеки чи плагіна JaCoCo. Парсинг CSV реалізований вручну, а окремий звіт покриття тестами не налаштований.

### `data/input.csv`

Файл не має заголовка. Кожен запис очікується у форматі:

```text
назва;автор;сторінки;ціна
```

Розділювач — крапка з комою `;`. Усі числові поля подаються десятковими символами; поточний парсер ціни використовує `Double.parseDouble`, тому у вхідному форматі десятковий розділювач має бути крапкою.

Наявні рядки:

| Рядок | Дані / випадок | Очікувана поведінка реалізації |
|---|---|---|
| 1 | `Кобзар;Тарас Шевченко;720;450.00` | Коректний запис; враховується у статистиці. |
| 2 | `Тіні забутих predkiv;Михайло Коцюбинський;192;220.50` | Коректний запис; враховується у статистиці. Назва містить латинське слово, яке не впливає на парсинг. |
| 3 | `Місто;Валер'ян Підмогильний;320;310.00` | Коректний запис; враховується у статистиці. |
| 4 | `Некоректний рядок;Невідомий автор;помилка_числа;150.00` | Некоректне числове поле сторінок; буде додано помилку `нечислове значення`. |
| 5 | `Пошкоджена книга;Автор;-50;100.00` | Некоректна кількість сторінок; буде додано помилку про нульове/від'ємне значення. |

Рядок розбивається методом `split(";", -1)`. Значення `-1` зберігає кінцеві порожні поля, завдяки чому рядок на кшталт `Назва;Автор;100;` дає чотири поля й може бути відхилений саме як помилка числового значення, а не помилкова кількість колонок.

### `src/main/java/ua/lpnu/kzp/Main.java`

#### Структура класу та запуск

`Main` — фінальний службовий клас з приватним конструктором і статичним методом `main(String[] args)`. Екземпляри класу створювати не потрібно.

Початкові шляхи:

- `Path.of("data", "input.csv")` — вхідний файл;
- `Path.of("out", "report.txt")` — вихідний звіт.

`Path.of` формує системно-залежний об'єкт шляху через стандартний файловий провайдер Java. Використання окремих компонентів шляху, а не ручних `/` чи `\\`, робить ці два шляхи переносимими між Windows і Unix-подібними системами. Шляхи відносні до поточного робочого каталогу процесу, а не обов'язково до розташування JAR.

#### Аргументи командного рядка

Цикл проходить `args` і розпізнає:

- `--help` — друкує підказку та завершує `main`;
- `--input <файл>` — замінює шлях до вхідного файлу;
- `--output <файл>` — замінює шлях до звіту.

Шлях створюється як `Path.of(args[i + 1])`. Якщо після `--input` або `--output` немає значення, параметр просто не застосовується. Невідомі аргументи ігноруються. Підказка показує приклад `lab01.jar`, але фактична назва shade-артефакту має classifier `all` і визначається версією Maven-проєкту.

#### Читання та валідація

1. Якщо `Files.exists(inputPath)` повертає `false`, програма друкує повідомлення про відсутній файл і припиняє обробку.
2. Файл цілком читається через `Files.readAllLines(inputPath, StandardCharsets.UTF_8)`. `IOException` перехоплюється, виводиться повідомлення про читання, після чого метод завершується.
3. Для кожного рядка прибираються зовнішні пробіли методом `trim()`. Порожні рядки пропускаються.
4. `split(";", -1)` розбиває рядок; очікується рівно чотири поля. Інша кількість полів додає помилку з номером рядка.
5. Назва й автор перевіряються через `String.isBlank()`. Порожнє або пробільне значення додає помилку. Це перевірка виконання, не анотація Bean Validation `@NotBlank`.
6. Сторінки розбираються як `int`, ціна — як `double`; числові поля перед парсингом обрізаються через `trim()`.
7. `NumberFormatException` перехоплюється, запис додає повідомлення про нечислове значення.
8. `pages <= 0` відхиляє нульову або від'ємну кількість сторінок. `price < 0` відхиляє від'ємну ціну. Нульова ціна дозволена.
9. Лише після успіху всіх цих перевірок запис додається до статистики.

#### Статистичні показники

- `validCount` — кількість коректних записів.
- `totalPages` — сума сторінок коректних записів.
- `avgPages` — середня кількість сторінок: `totalPages / validCount`, ділення виконується в `double`. Якщо коректних записів немає, значення дорівнює `0.0`.
- `maxPrice` — максимальна ціна серед коректних записів; початкове значення `Double.NEGATIVE_INFINITY`.
- `actualMaxPrice` — максимальна ціна для звіту; якщо коректних записів немає, дорівнює `0.0`.
- `totalPrice` — сума цін коректних записів.
- `errors` — список повідомлень про відхилені непорожні рядки.

#### Формування та збереження звіту

Звіт збирається через `StringBuilder`; рядки додаються викликами `append`. Числа та повідомлення формуються через `String.format(Locale.ROOT, ...)` або `String.formatted(...)`. Для числових форматів застосовується `Locale.ROOT`, зокрема `%.2f`, щоб відображення десяткової крапки не залежало від локалі системи. Перенос рядка задається `%n`.

У коді немає побудови тексту звіту через конкатенацію рядків оператором `+`. Оператор `+` також не потрібен для шляхів: компоненти передаються окремо до `Path.of`.

Після побудови звіт перетворюється на `String`, виводиться через `System.out.print`, а потім записується методом `Files.writeString(..., StandardCharsets.UTF_8)`. Перед записом створюється батьківський каталог вихідного шляху через `Files.createDirectories`, якщо він є. Помилка запису перехоплюється й друкується в консоль; код не встановлює ненульовий код завершення процесу.

### `src/test/java/ua/lpnu/kzp/MainTest.java`

Тестовий клас містить два тести JUnit Jupiter:

1. **`testAverageCalculation`** — обчислює середнє `912 / 3` і перевіряє `assertEquals(expectedAverage, actualAverage, 0.0001, ...)`. Допуск порівняння — `0.0001`. Тест перевіряє арифметичний приклад окремо, а не викликає код статистики `Main`.
2. **`testCsvParsingLogic`** — розбиває один коректний рядок на чотири поля методом `split(";", -1)`, перевіряє кількість через `assertEquals(4, fields.length)`, назву через `assertEquals("Кобзар", fields[0])` і позитивність розібраної кількості сторінок через `assertTrue(...)`.

Тести не запускають `Main.main`, не читають `data/input.csv`, не перевіряють сформований звіт, помилки вводу/виводу, параметри CLI або SpotBugs. Не слід трактувати їх як повне інтеграційне покриття програми.

### `README.md`

Короткий опис роботи програми українською: читає `data/input.csv`, перевіряє записи, обчислює статистику та створює звіт у консолі й `out/report.txt`.

## 4. Взаємодія компонентів та загальний звіт

### Потік даних під час роботи застосунку

1. JVM запускає `ua.lpnu.kzp.Main.main`.
2. `Main` визначає шляхи за замовчуванням і обробляє параметри командного рядка.
3. Програма перевіряє існування вхідного файла та читає його як UTF-8.
4. `Main` обробляє рядки послідовно, перевіряє формат, поля та числа.
5. Коректні записи впливають на статистику; некоректні потрапляють до списку помилок.
6. Результат формується одним текстом, виводиться у консоль і записується в зазначений вихідний файл.

### Життєвий цикл Maven

Команда `mvn clean verify` проходить стандартні фази Maven у порядку:

1. **`clean`** — видаляє попередній каталог `target/`.
2. **`compile`** — компілює `src/main/java` з `release 21` у `target/classes`.
3. **`test`** — компілює тести та запускає їх Surefire/JUnit Platform; звіти тестів потрапляють у `target/surefire-reports`.
4. **`package`** — створює JAR і виконує Shade Plugin, який додає зібраний артефакт з classifier `all` та головним класом у маніфесті.
5. **`verify`** — виконує перевірки, прив'язані до цієї фази; у цьому проєкті запускається SpotBugs `check`. Якщо аналіз не проходить, повна команда `verify` завершується невдало навіть за успішних компіляції та тестів.

### Що критичне для стабільної роботи

- JDK 21 для запуску та Maven-компіляції відповідно до заданої цілі.
- Apache Maven 3.9.x і доступ до Maven Central під час першого отримання залежностей/плагінів.
- Збереження `maven.compiler.release=21`.
- Узгодженість імені пакета `ua.lpnu.kzp` з розташуванням Java-файлів.
- Наявність вхідного файла або коректний `--input`; правильна структура з чотирьох полів через `;`.
- Запуск із робочого каталогу, відносно якого існує `data/input.csv`, або передача явного шляху.
- Сумісність змін із JUnit Jupiter, Surefire та вимогами SpotBugs.

## 5. Критичні технічні нюанси та підводні камені для майбутнього

### Властивості реалізації, які треба зберегти

- **Форматування:** `String.format` та `String.formatted` створюють повідомлення за шаблоном; `StringBuilder` збирає фінальний документ без конкатенації рядків оператором `+`.
- **Локаль:** `Locale.ROOT` використовується для незалежного від регіональних налаштувань форматування чисел. Не прибирати його з грошових і середніх значень: вивід має стабільно використовувати десяткову крапку.
- **Переносимість шляхів:** `Path.of` і `Files` уникають жорстко заданих розділювачів каталогів. Водночас відносні шляхи залежать від поточного робочого каталогу.
- **Кодування:** вхідний і вихідний файли явно обробляються як UTF-8; зберігати це при зміні вводу/виводу.
- **Збереження кінцевих порожніх CSV-полів:** не змінювати `split(";", -1)` на варіант без ліміту, бо стандартний `split` відкидає кінцеві порожні підрядки.
- **Звіт про помилки:** рядки нумеруються від 1 через `index + 1`; не зміщувати індекс під час рефакторингу.

### Мінне поле для наступних змін

- Не підвищувати версію Java самостійно: навчальне середовище вимагає Java 21 LTS, а POM фіксує `release 21`.
- Не замінювати `release` лише на `source`/`target` без усвідомленого рішення: поточна конфігурація задає і мовну, і API-сумісність Java 21.
- SpotBugs запускається саме на `verify`. Успішний `compile` або `test` не доводить успіху `mvn clean verify`; аналізувати повний лог до фінального підсумку.
- Shade Plugin виконується в `package`, яке передує `verify`; зміна головного класу або конфігурації маніфесту може зламати запуск JAR, навіть якщо тести проходять.
- Не вважати тести інтеграційними: зараз вони повторно перевіряють окрему арифметику та приклад поділу рядка, а не фактичний конвеєр застосунку.
- Додаткові обмеження, які варто врахувати при розширенні валідації: `Double.parseDouble` допускає `NaN` та нескінченні значення; перевірка `price < 0` їх не відхиляє. Для суворих грошових даних потрібна явна перевірка скінченності, а для точних сум — розгляд `BigDecimal`.
- `totalPages` типу `int` може переповнитися на надзвичайно великих наборах даних; `double` накопичує округлення для сум цін. Поточний приклад невеликий, але масштабування потребує окремих тестів і вибору типів.
- `Files.readAllLines` завантажує весь файл у пам'ять. Для дуже великих каталогів слід оцінити потокове читання, зберігши нумерацію рядків і поведінку звіту.
- `REPORT.md` наразі порожній. Не використовувати його як джерело вимог або результатів без оновлення вмісту.
